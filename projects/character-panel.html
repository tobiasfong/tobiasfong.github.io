MCP Server Project

Character & Panel Generator

A local MCP server that keeps a webcomic's characters looking like themselves — register your reference art once, then generate poses, turnaround sheets and finished panels that stay on-model.

MCP Server Python ComfyUI FLUX.1 Kontext Built with Claude
What It Is

For writers who aren't artists

And for artists who'd rather not redraw the same character six times before page one.

You register whatever reference art you already have — commissioned, AI-generated, or one good drawing — into a Character Bible. From there, the server generates new poses, genuine back views and turnaround sheets that stay recognizably the same character, then composites them onto background plates into finished panels.

It wraps a local ComfyUI + Stable Diffusion / FLUX pipeline, runs entirely on your own machine, and is the character-domain sibling of the Webcomic Background Generator's World Builder. That server handles places. This one handles people.

The Catch

Text-to-image gives you a different person every time

That's fine for a single illustration. For a comic it's fatal. Readers track characters by hair, eyes, costume and silhouette — drift between panels doesn't read as "a slightly different render," it reads as a continuity error, or worse, as a different character entirely.

So the entire design follows from one principle: reference-driven, never generate-from-text-and-pray. The registered art is the ground truth for who a character is, and every single generation conditions on it. If you can't point at the reference a panel came from, the tool considers that a bug, not a style.

Step One

Character concepts

Everything starts here. A character gets a reference sheet — front, back, expressions, props, an action pose — and that sheet becomes the ground truth every later panel is generated against. Both of these were produced by the server itself, from nothing but a written description.

Under The Hood

How it works

The Character Bible

A per-project registry holding each character's description, an ordered list of reference images, and provenance — which approved sheet each reference was cropped from. Projects namespace characters per comic, so a crossover can pull from two of them without either one's canon leaking into the other.

A three-tier identity stack, so quality scales with hardware

Tier 1 (always on) is prompt + LoRA styling, and needs nothing beyond a working ComfyUI. Tier 2 (opt-in per call) adds IP-Adapter identity conditioning and ControlNet pose control. Tier 3 bakes a per-character LoRA for the strongest lock available locally. You're never forced to pay for a tier your GPU can't run.

3D pose control, because prompts can't force a direction

An OpenPose or depth map is rendered from a posable 3D skeleton at any angle. Reference sheets are almost always frontal, and no amount of prompting reliably produces a genuine back view — this is the same "geometry first, diffusion only paints" principle the background server uses for its cities and props, applied to bodies.

Validation as a gate, not a suggestion

A checker exits non-zero if a reference is missing, if an unregistered image is lurking in a character folder, or if the primary reference can't be traced back to an approved sheet. That check exists for a reason: a silently wrong reference once propagated a character's wrong hair colour through thirteen panels before anyone noticed.

Compositing is separate from generation

Cutout, placement, panel assembly and strip layout are deterministic CPU operations — instant to iterate, no GPU, no tokens. Only generation is expensive. "Move her two hundred pixels left" should never cost a re-render, and here it doesn't.

Step Two

The human still decides what's in the panel

I storyboarded the whole scene by hand first — fifteen panels, rough as anything. Composition, camera, staging and acting are decisions, and decisions are the part I'm not delegating. The server renders what the storyboard already worked out.

Step Three

What came out, and what each one proves

These aren't here because they're pretty. Each one is doing something that's genuinely hard to get out of a diffusion model, so the captions name the capability rather than the plot.

A matched pair. Two separate generations, two different characters, cropped and lit to sit side by side in the same beat — generated independently, then composited as a single panel.

The Proof

It goes all the way to a deliverable

Individual nice images prove very little. What matters is whether the thing assembles into something you could actually publish — so the fifteen panels were laid out into a finished vertical strip, the format a webtoon reader actually scrolls through.

It's also the first real test of a proper comic reader on this site, which A Starry Knight has been waiting on. Two birds.

The Toolbox

Roughly twenty tools

Bible register_character, get_character, list_characters, forget_character, list_projects
Concept genesis generate_character_concept, crop_reference, generate_reference_sheet, generate_turnaround_sheet, compose_reference_sheet — for getting a character into the bible from nothing, from a composite sheet, or from a single drawing
Posing generate_pose_map, generate_pose_depth_map, generate_character_pose
Finishing edit_character_image, apply_gradient_background, apply_vfx_overlay, compose_panel
LoRA training bake_character_lora, check_lora_training, cancel_lora_training

Under the hood: Python, FastMCP over stdio. Local ComfyUI driving FLUX.1 Kontext dev (GGUF quantised) for identity-conditioned editing, Stable Diffusion 1.5 for the legacy tier, ControlNet Union for pose and lineart, IP-Adapter for identity, and a manhwa/webtoon style LoRA. Developed against a 6 GB laptop GPU — the quantised models and the CPU-side compositing are both consequences of that constraint, and both turned out to be good ideas anyway.

Honestly

What the production run actually taught me

Fifteen panels sounds small. It wasn't — it's where most of this server's hard-won rules came from, and they're written down in the repo so the next person doesn't have to rediscover them. The biggest one: the background and the figures have to share a projection, or the panel reads as pasted no matter how carefully you match the colour. I spent a long time adjusting hue and shadow on panels whose real problem was that the camera didn't agree with itself.

The early panels needed heavy hand repair. The late ones needed much less — not because the model got better, but because I did. That's the honest shape of this kind of tooling: it doesn't remove the craft, it moves where you spend it. Same conclusion I reached translating my novel, from the opposite direction.

For everyone's use

Get the code

Third personal MCP server, same origin pattern as the others: built to fix a real problem I hit doing my own work, not a speculative feature. It lives in webcomic-toolkit alongside the Webcomic Background Generator, the Novel Translation server and the Anime Production Skill.

Each installs independently — there's no code dependency between this and the background server, they just point at the same local ComfyUI. Character & Panel handles people; Background handles places; this one composites onto the other one's plates. Everything runs on your own GPU, with no cloud and no per-image cost.
